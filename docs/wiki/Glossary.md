# Glossary 📖

This glossary defines technical terms across IBM Spectrum Virtualize, Zabbix monitoring, and the collector architecture.

---

### IBM FlashSystem & Spectrum Virtualize Terminology

- **Canister (Node)**: An individual physical controller compute module containing CPUs, DRAM cache, PCIe interconnects, and Fibre Channel adapters. A FlashSystem enclosure typically contains two canisters operating as a redundant pair.
- **Cluster Management IP**: The virtual, floating IP address that provides management and CLI access across the clustered pair of canisters.
- **Enclosure**: The physical 2U shelf containing canisters, power supply units (PSUs), backup batteries, and drive bays.
- **FlashCopy**: IBM's point-in-time volume snapshot and volume cloning feature (`lsfcmap`).
- **I/O Group**: A logical pair of node canisters that manages a designated set of virtual disks (volumes).
- **MDisk (Managed Disk)**: A physical drive array or external SAN LUN presented to Spectrum Virtualize for storage virtualization.
- **MDisk Group (Storage Pool)**: A storage pool constructed from one or more MDisks, from which virtual volumes allocate capacity.
- **Spectrum Virtualize**: The core virtualization operating system powering IBM FlashSystem, Storwize, and SAN Volume Controller (SVC).
- **`svcinfo`**: The read-only informational CLI command namespace on Spectrum Virtualize arrays.
- **`svctask`**: The administrative configuration and modification CLI command namespace.
- **VDisk (Volume)**: A virtual block disk presented over Fibre Channel, iSCSI, or NVMe-oF to host operating systems.

---

### Zabbix Monitoring Terminology

- **Dependent Item**: An item that extracts its metric data directly from the raw value of a Master Item, avoiding additional polling overhead.
- **External Check**: A Zabbix item type that executes a shell script or binary on the Zabbix server or proxy host filesystem.
- **Low-Level Discovery (LLD)**: A mechanism that dynamically discovers infrastructure components (e.g., drives, pools) and creates prototype items and triggers.
- **Master Item**: A primary item that retrieves an entire payload (often a large JSON object) from an external data source in a single request.
- **Preprocessing**: Transformations (JSONPath, JavaScript, regex) applied to raw item values before storing them in the Zabbix database.
- **User Macro**: A host-level or template-level variable (e.g., `{$FS_COLLECT_INTERVAL}`) used to customize polling schedules or threshold limits.

---

### Collector Engine Terminology

- **Atomic Rename**: Using POSIX `rename(2)` to commit temporary cache files directly over existing cache paths, preventing file corruption during process interruption.
- **Master JSON Envelope**: The structured JSON payload generated by `internal/zabbix/output.go` combining 12 collector domains into a unified object.
- **Stale Fallback**: Re-serving previously cached records that have exceeded their TTL when the remote storage system is unreachable over SSH.
- **Truncation Safeguard**: Logic that progressively pares down volume and drive records to prevent the final stdout JSON payload from exceeding `MaxJSONBytes`.
